## 一句话总结

作者做完「模拟面试 skill」后，被粉丝追问“能不能把模拟出的弱点回改到简历、直接帮忙写简历”，于是做了一个**全流程把你稳稳托住**的简历 skill：整理经历 → 生成简历 → 模拟面试追问 → 回改定稿。它最反常规的一点是：**只写你说过的内容，不做幻觉生成**——因为“简历投出去没事，面试官问一句‘这数怎么测的’就直接寄了”。

---

## 它能做什么

经历采集 · 贡献拆分 · STAR 改写 · JD 匹配修改，并能丝滑衔接：模拟面试 · 弱项复训 · 多格式导出。

适用于 **Claude Code、Codex 和其他可读 SKILL.md、运行本地脚本的 AI Agent**。中文排版优化，本地离线渲染。

---

## 核心特色（6 条）

1. **只写你说过的**：每条简历内容对应你讲过的具体经历，不补充你没提供的数字。
2. **数字按来源分级**：你测量过的 / 你记不清怎么得来的 / 只有覆盖范围没有比例的 / 完全没有 的——四类分别用不同写法。
3. **区分个人贡献与团队贡献**：回答中出现“我们”时，会追问其中哪部分由你完成。
4. **内容体检**：为每条要点生成面试可能追问的问题，答不上来的标出并给出改法。
5. **从经历到成品的完整流程**：对话采集 → 内容改写 → JD 匹配 → 文件导出。
6. **对话式经历采集**：依次追问**场景、你的动作、当时的判断、结果、量化**，五项问完才进入下一段。

## 处理流程

```
经历采集（对话 / 已有简历 / 项目材料）
   → 全量经历，不做删减、不做润色
内容审查 → 无来源的数字剥离，缺失项退回补充
定向匹配 → 命中项 / 缺失项 / 内容顺序
改写与排版 → 只在审查通过的内容里操作
内容体检 → 逐条生成面试追问，答不上来的回改
产出 → 简历 + 压测清单 + 追问清单
```

- 换一个岗位时，从 `profile.md` 往下重跑，**不需要重新采集经历**。
- 提供欲投递岗位 JD / 描述后，对项目经历做命中判断、匹配经历迁移、贡献度深度拆分。
- 改写排版提供多种模板可下载。
- 内容体检（可选）可自动衔接“模拟面试.skill”。

**一轮对话即可生成**：简历文件 / 目标岗位差距分析 / 经历-模拟面试问题 / 可复用经历库。

## 压测清单（示例）

场景：AI 算法工程师，目标城市 北上广深杭。

**判定规则**：一个 bullet 挂 2 层及以上“答不上来”，视为虚的，打回重改。用法：自己出声答一遍，答不上来的当场改简历，不要留到面试现场。

**高风险表述（claimed 级，优先处理）示例：**

> bullet 1：「精排请求耗时下降约 99%」
- **L1 数字来源**：这个 99% 怎么测的？测的是 QPS 峰值还是日均？基线是哪天的数据？是因为波动还是因为你没量过？
- **L2 决策归属**：队列结构原来什么样、你改成了什么？这个改动是你提的还是 mentor 定的方案？
- **L3 边界条件**：如果广告吞吐翻倍，你这个结构还成立吗？特征复用的缓存命中率是多少？
- **L4 持续性**：你离职后这个模块还在线上跑吗？有没有被后来的人推翻？
- **改法**：答不出 L1 就删掉 99%，改成“重构精排打分请求模块，通过队列结构调整与特征复用降低请求耗时”。

> bullet 2：「下游手动填写配置内容减少 80%」
- **L1 分母是什么**：配置字段数、配置文件行数，还是下游同学的填写工时？
- **L2 为什么以前没人做**：是没人意识到，还是历史配置格式没法统一？
- **L3 换一个新模型类型，你的转换脚本还能复用吗？还是要改代码？**
- **L4 下游几个团队在用它？现在还在用吗？**
